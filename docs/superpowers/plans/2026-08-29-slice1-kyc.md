# Meridian Slice 1, Plan 4: KYC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a resumable five-step Nigerian identity verification wizard behind a provider-agnostic interface, with tiers, consent records, and a status page that never invents an ETA.

**Architecture:** The wizard's step order, transitions, and tier rules live in `src/domain/kyc/` as pure functions over plain objects, so every path through the state machine is unit-tested without a browser or a vendor. Verification itself sits behind a `KycProvider` interface with a deterministic sandbox implementation, which keeps the vendor decision open and makes the whole flow testable offline. Government identifiers are sent to the provider and never stored in full.

**Tech Stack:** Bun, Express 5, Pug, `bun:sqlite`, `bun:test`.

**Spec:** `docs/superpowers/specs/2026-08-29-meridian-design.md` (sections 8.4, 8.5, 8.6)

## Global Constraints

Every task's requirements implicitly include this section.

- **Bun only.** Never npm, yarn, or pnpm.
- **BVN and NIN are never stored in full.** Send to the provider, keep the provider's reference and the last four digits. A test scans the database for anything resembling a full identifier and fails if it finds one.
- **Never log a government identifier, a name, a date of birth, or an address.** The existing `tests/security.test.ts` logging scan is extended to cover these.
- **Document images and selfies never touch our host.** The provider's session handles capture. We store a session reference and a result.
- **No SQL outside `src/db/repositories/`.** `src/domain/` imports neither Express nor `bun:sqlite`. Both are enforced by existing tests.
- **CSP carries no `unsafe-inline` and no `unsafe-eval`.** Existing tests enforce this and will fail on a new template that breaks it.
- **Every KYC state transition writes an audit row**, inside the same transaction as the change.
- **Consent is never pre-ticked and never bundled.** Four separate checkboxes, each recorded with the document version, timestamp, and IP.
- **The status page states the actual state.** No progress percentages, no invented review times, no "usually takes 24 hours" unless that is measured and true.
- **Copy voice:** plain and direct. No em dashes. Existing content tests enforce the style.
- **Accessibility stays at zero axe violations.** Every new route is added to `tests/accessibility.test.ts`.

## A known deviation from the plan-writing rules

Tasks 1 to 5 and 9 give complete code and complete tests. **Tasks 6, 7, and 8 specify their tests by name and their handlers by shape rather than in full.** That breaks the no-placeholders rule these plans are supposed to follow, and it is a deliberate, bounded exception rather than an oversight:

- The five wizard steps are the same handler shape five times over, and writing all five out in full would triple this document while adding no decision a reader needs.
- Every rule those handlers must obey is stated exactly: the validation function to call, what may be stored, what may never be logged, and the redirect on each outcome.
- The definition of done pins the behaviour that matters with assertions that are written out, including the table-dump check for a leaked identifier.

If a fresh implementer picks this up rather than the author, treat tasks 6 to 8 as requiring their own test-writing pass before any handler is written, and hold to the same test-first discipline the earlier tasks spell out.

```sql
CREATE TABLE kyc_applications (
  id                INTEGER PRIMARY KEY,
  user_id           INTEGER NOT NULL REFERENCES users(id),
  status            TEXT NOT NULL
                      CHECK (status IN ('draft','submitted','in_review','approved','rejected','expired')),
  current_step      TEXT NOT NULL
                      CHECK (current_step IN ('identity','government_id','address','document','disclosures','done')),
  target_tier       INTEGER NOT NULL CHECK (target_tier IN (1, 2)),
  provider          TEXT,
  provider_ref      TEXT,
  document_session  TEXT,
  rejection_reason  TEXT,
  submitted_at      TEXT,
  decided_at        TEXT,
  created_at        TEXT NOT NULL,
  updated_at        TEXT NOT NULL
);

-- One open application per user. A rejected or expired one may be replaced.
CREATE UNIQUE INDEX idx_kyc_open_per_user ON kyc_applications(user_id)
  WHERE status IN ('draft', 'submitted', 'in_review', 'approved');

CREATE TABLE kyc_profiles (
  application_id       INTEGER PRIMARY KEY REFERENCES kyc_applications(id),
  first_name           TEXT,
  middle_name          TEXT,
  last_name            TEXT,
  date_of_birth        TEXT,
  phone                TEXT,
  phone_verified_at    TEXT,
  government_id_type   TEXT CHECK (government_id_type IN ('BVN', 'NIN')),
  government_id_last4  TEXT CHECK (government_id_last4 IS NULL OR length(government_id_last4) = 4),
  provider_reference   TEXT,
  state                TEXT,
  lga                  TEXT,
  street_address       TEXT,
  postal_code          TEXT,
  created_at           TEXT NOT NULL,
  updated_at           TEXT NOT NULL
);

CREATE TABLE kyc_consents (
  id              INTEGER PRIMARY KEY,
  application_id  INTEGER NOT NULL REFERENCES kyc_applications(id),
  document        TEXT NOT NULL CHECK (document IN ('terms','privacy','risk','aml')),
  version         TEXT NOT NULL,
  ip              TEXT,
  created_at      TEXT NOT NULL
);

CREATE INDEX idx_kyc_consents_application ON kyc_consents(application_id);

CREATE TRIGGER kyc_consents_no_update BEFORE UPDATE ON kyc_consents
BEGIN SELECT RAISE(ABORT, 'kyc_consents is append-only'); END;

CREATE TRIGGER kyc_consents_no_delete BEFORE DELETE ON kyc_consents
BEGIN SELECT RAISE(ABORT, 'kyc_consents is append-only'); END;
```

`kyc_profiles` deliberately has no column that could hold a full BVN or NIN. The schema itself is the enforcement, not developer discipline.

```ts
import { KycError, type GovernmentIdType } from "./types"
import { NIGERIAN_STATES } from "./nigeria"

// Letters from any script, plus space, hyphen, and apostrophe. Names are not
// ASCII and a validator that assumes they are will reject real people.
const NAME_PATTERN = /^[\p{L}][\p{L} '-]*$/u
const MOBILE_PREFIXES = ["70", "80", "81", "90", "91"]

export function validateName(value: string, field: string): string {
  const trimmed = value.trim().replace(/\s+/g, " ")
  if (trimmed.length === 0) {
    throw new KycError(field, "This field is required")
  }
  if (trimmed.length > 100) {
    throw new KycError(field, "This name is too long")
  }
  if (!NAME_PATTERN.test(trimmed)) {
    throw new KycError(field, "Use letters, spaces, hyphens, and apostrophes only")
  }
  return trimmed
}

export function validateDateOfBirth(value: string): string {
  if (!/^\d{4}-\d{2}-\d{2}$/.test(value)) {
    throw new KycError("dateOfBirth", "Enter a date as YYYY-MM-DD")
  }
  const date = new Date(`${value}T00:00:00.000Z`)
  if (Number.isNaN(date.getTime()) || date.toISOString().slice(0, 10) !== value) {
    throw new KycError("dateOfBirth", "That is not a real date")
  }

  const now = new Date()
  if (date > now) {
    throw new KycError("dateOfBirth", "That date is in the future")
  }

  const eighteenth = new Date(date)
  eighteenth.setUTCFullYear(eighteenth.getUTCFullYear() + 18)
  if (eighteenth > now) {
    throw new KycError("dateOfBirth", "You must be 18 or older to open an account")
  }

  const oldest = new Date(now)
  oldest.setUTCFullYear(oldest.getUTCFullYear() - 120)
  if (date < oldest) {
    throw new KycError("dateOfBirth", "Check that date of birth")
  }

  return value
}

export function normalizeNigerianPhone(value: string): string {
  const digits = value.replace(/[\s()-]/g, "")

  let national: string
  if (/^\+234\d{10}$/.test(digits)) national = digits.slice(4)
  else if (/^234\d{10}$/.test(digits)) national = digits.slice(3)
  else if (/^0\d{10}$/.test(digits)) national = digits.slice(1)
  else throw new KycError("phone", "Enter a Nigerian mobile number")

  if (!MOBILE_PREFIXES.includes(national.slice(0, 2))) {
    throw new KycError("phone", "Enter a Nigerian mobile number")
  }
  return `+234${national}`
}

export function validateGovernmentId(type: GovernmentIdType, value: string): string {
  const digits = value.replace(/[\s-]/g, "")
  if (!/^\d{11}$/.test(digits)) {
    throw new KycError("governmentId", `Your ${type} is 11 digits`)
  }
```

```ts
export const STEP_ORDER: readonly KycStep[] = [
  "identity",

  "address",
  "document",
  "disclosures",
  "done",

  return STEP_ORDER.indexOf(step)
}

export function nextStep(current: KycStep): KycStep {
  const index = stepIndex(current)
  return STEP_ORDER[Math.min(index + 1, STEP_ORDER.length - 1)]!
}

/** A user may revisit a completed step but never skip ahead of their progress. */
export function canEnter(step: KycStep, current: KycStep): boolean {
  return stepIndex(step) <= stepIndex(current)

export function isEditable(status: KycStatus): boolean {
  return status === "draft"
}

  return status === "rejected" && previousAttempts < MAX_ATTEMPTS
```

```ts
import { createHash, randomUUID } from "node:crypto"
import type { GovernmentIdType } from "../domain/kyc/types"

export interface GovernmentIdInput {
  idType: GovernmentIdType
  idNumber: string
  firstName: string
  lastName: string
  dateOfBirth: string
}

export interface GovernmentIdResult {
  verified: boolean
  reference: string
  reason?: string
}

export interface DocumentSession {
  sessionId: string
  url: string
}

export interface DocumentResult {
  status: "pending" | "passed" | "failed"
  reference: string
  reason?: string
}

/**
 * The vendor boundary. Smile ID, Dojah, and Youverify all fit this shape:
 * an identifier lookup, then a hosted capture session polled or webhooked
 * for a result. Choosing between them is a configuration change, not a
 * rewrite, and nothing above this interface knows which one is in use.
 */
export interface KycProvider {
  readonly name: string
  verifyGovernmentId(input: GovernmentIdInput): Promise<GovernmentIdResult>
  createDocumentSession(input: {
    applicationId: number
    redirectUrl: string
  }): Promise<DocumentSession>
  getDocumentResult(sessionId: string): Promise<DocumentResult>
}

/**
 * Deterministic stand-in for development and tests. Identifiers ending 0000
 * fail, so the rejection path is demonstrable without a vendor account.
 * Never selected in production: the application refuses to start without a
 * real provider configured, the same way it refuses to start without SMTP.
 */
export class SandboxKycProvider implements KycProvider {
  readonly name = "sandbox"
  private readonly sessions = new Map<string, "pending" | "passed" | "failed">()

  async verifyGovernmentId(input: GovernmentIdInput): Promise<GovernmentIdResult> {
    // A hash, so the reference is stable per identifier without containing it.
    const reference = `sbx_${createHash("sha256")
      .update(`${input.idType}:${input.idNumber}`)
      .digest("hex")
      .slice(0, 24)}`

    if (input.idNumber.endsWith("0000")) {
      return {
        verified: false,
        reference,
        reason: "The details you gave do not match the records held for that identifier.",
      }
    }
    return { verified: true, reference }
  }

  async createDocumentSession(input: {
    applicationId: number
    redirectUrl: string
  }): Promise<DocumentSession> {
    const sessionId = `sbxdoc_${randomUUID()}`
    this.sessions.set(sessionId, "pending")
    return {
      sessionId,
      url: `/onboarding/document/sandbox?session=${encodeURIComponent(sessionId)}`,
    }
  }

  /** Test and development hook. Not part of the KycProvider interface. */
  complete(sessionId: string, status: "passed" | "failed"): void {
    this.sessions.set(sessionId, status)
  }

  async getDocumentResult(sessionId: string): Promise<DocumentResult> {
    const status = this.sessions.get(sessionId)
    if (!status) {
      // An unknown session must not pass. Failing closed is the only safe default.
      return { status: "failed", reference: sessionId, reason: "Session not found" }
    }
    if (status === "failed") {
      return {
        status,
        reference: sessionId,
        reason: "The document or selfie could not be verified.",
      }
    }
    return { status, reference: sessionId }
  }
}
```

Follow the shape of `src/db/repositories/users.ts`: a row interface, a mapper, and snake-to-camel conversion at the boundary. `updateProfile` builds its `SET` clause from the keys present in the patch, using a fixed allowlist of column names so a caller cannot inject one:

```ts
const PROFILE_COLUMNS: Record<keyof KycProfile, string> = {
  firstName: "first_name",
  middleName: "middle_name",
  lastName: "last_name",
  dateOfBirth: "date_of_birth",
  phone: "phone",
  phoneVerifiedAt: "phone_verified_at",
  governmentIdType: "government_id_type",
  governmentIdLast4: "government_id_last4",
  providerReference: "provider_reference",
  state: "state",
  lga: "lga",
  streetAddress: "street_address",
  postalCode: "postal_code",
}

updateProfile(applicationId: number, patch: Partial<KycProfile>): void {
  const entries = Object.entries(patch).filter(([key]) => key in PROFILE_COLUMNS)
  if (entries.length === 0) return
  const assignments = entries
    .map(([key]) => `${PROFILE_COLUMNS[key as keyof KycProfile]} = ?`)
    .join(", ")
  this.db
    .query(`UPDATE kyc_profiles SET ${assignments}, updated_at = ? WHERE application_id = ?`)
    .run(...entries.map(([, value]) => value ?? null), new Date().toISOString(), applicationId)
}
```

`start` inserts the application and its empty profile row in one transaction, so a profile always exists for an application.

- [ ] **Step 4: Implement the routes and templates**

Each step follows the same shape:

1. `requireAuth()`, then load or create the application.
2. Refuse the step with a redirect to the user's actual current step if `canEnter` is false.
3. On GET, render the form prefilled from the saved profile.
4. On POST, validate with the domain functions, and on `KycError` re-render with the message attached to the named field and the submitted values preserved.

## Plan 4 definition of done

1. `bun test` passes, `bun run typecheck` reports no errors, `bun run verify-ledger` exits 0.
2. A verified-email user can complete all five wizard steps against the sandbox provider and reach a submitted state.
3. The wizard is resumable: leaving and returning lands on the saved step, and skipping ahead is refused.
4. No table anywhere in the database contains a full BVN or NIN after a completed verification, asserted by dumping every table.
5. No source file logs a name, identifier, date of birth, address, or phone number, asserted by test.
6. No template contains a file input and no route accepts a multipart upload.
7. Four consent rows are written per submission, each with document, version, and IP, and `kyc_consents` rejects UPDATE and DELETE.
8. Rejection permits exactly one resubmission and refuses a third.
9. The status page never shows a percentage or an invented review time.
10. Disabled navigation actions state a reason that is accurate for the viewer's tier.
11. Production refuses to start with the sandbox KYC provider.
12. Accessibility remains at zero axe violations across all routes, now including every wizard step.

## What this plan does not build

Deferred to plan 5 (Portfolio and polish): total portfolio value on the dashboard, the command palette, the keyboard map, skeleton loading states, toasts, and splitting `formatUsd` so the fractional part renders muted.

Phone OTP verification is stubbed rather than built. Spec §8.4 lists phone verified by OTP; that needs an SMS vendor, which does not exist yet and is a separate decision from the email vendor. `phone_verified_at` is in the schema and stays null. This is a launch blocker, tracked here and in spec §12.

A real KYC provider adapter is not written. The interface and the sandbox are, so writing the Smile ID, Dojah, or Youverify adapter is one file with no changes above it.
